## Turn Confusion into a Smaller Question

Being stuck is normal. Repeating random changes without recording results makes the problem harder to understand. Start by writing what you expected, what happened, and the smallest steps that reproduce it.

Check the first relevant error, the current working directory, and the project’s setup instructions. Change one variable at a time. Keep track of what each experiment rules out so you do not loop through the same guesses.

A useful request for help might be: “Running the documented build from the repository root fails with this missing-package error. The runtime matches the README. A fresh dependency install succeeds, but the build still fails. Is there a separate tool installation step?”

Use a timebox appropriate to the task’s urgency rather than disappearing for a day. Escalate early when a blocker affects other people or a release. Share sanitized diagnostics and a minimal example instead of credentials or a huge unrelated log.

## Practice

Rewrite “the app is broken” as a help request. **Check:** another developer should know the command, environment, expected result, actual failure, and experiments already attempted.
