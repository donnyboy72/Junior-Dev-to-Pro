## Start with a Real Need

Read the README, contribution guide, code of conduct, and license. Check whether the project is actively maintained and whether an existing issue or pull request already covers the problem.

Good first contributions can include correcting a verified documentation error, adding a missing regression case, improving an error message, or fixing a small reproducible bug. “Small” should describe the change’s scope, not the value of the work.

Reproduce the issue with the project’s supported environment before proposing a fix. Record the version, expected behavior, actual behavior, and minimum steps. Remove private data from examples.

For a larger feature, discuss the problem and likely approach before investing heavily. Maintainers may have compatibility requirements or an alternate plan. Follow the project’s issue templates and contribution rules instead of assuming every repository works the same way.

## Practice

Choose a local documentation issue and draft a contribution plan without posting it. **Check:** explain who benefits, how you confirmed the problem, which files are involved, and what evidence would demonstrate the correction.
